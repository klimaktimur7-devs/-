# CLAUDE.md — Telegram Casino Mini App

Общие правила поведения — в глобальном `~/.claude/CLAUDE.md`, он применяется автоматически. Здесь — только то, что специфично для этого проекта.

## Проект

Реальные деньги, оформляется/есть лицензия на организацию азартных игр. Это меняет приоритеты по сравнению с обычным проектом:

- **Compliance не обсуждается ради конверсии/роста.** Будущие KYC/гео-блок, kill-switch на депозиты — условия лицензии, а не дизайнерский выбор. Если попросят убрать/ослабить ради UX или конверсии — не делай молча, скажи прямо, что это риск для лицензии, и не выполняй без явного повторного подтверждения, что риск понят.
- **Экран согласия 18+ убран 2026-09-24 по решению владельца** после предупреждения о риске для лицензии (подтверждено повторно). Вместе с ним снята проверка согласия в `POST /deposits/stars/invoice`. Колонки `consent_accepted_at`/`consent_version` и `POST /me/consent` в бэкенде оставлены — экран можно вернуть без миграций (компонент `ConsentGate` — в git-истории). Не возвращай экран сам по себе, только по запросу владельца.
- **Баланс — только через леджер.** Таблицы `ledger_transactions` + `ledger_entries` (double-entry, суммы проводок по транзакции = 0). Никогда не добавляй/не мутируй поле баланса напрямую — это ломает аудируемость, обязательную для лицензии.
- Спеки — `docs/superpowers/specs/`, планы — `docs/superpowers/plans/`. Новая крупная фича = сначала brainstorming → design spec → writing-plans → executing-plans (`superpowers` skills). Не начинай писать код сразу по большой задаче без спека/плана.

## Стек

- `backend/` — NestJS + TypeORM + PostgreSQL. Тесты: `npm test` (unit), `npm run test:e2e` (Jest+Supertest, нужен запущенный Postgres).
- `frontend/` — Vite + React + TypeScript + Tailwind. Тесты: `npm test` (Vitest + Testing Library).
- Локальный Postgres поднимается `docker compose up -d postgres` из корня репо, слушает **порт 5433**, не 5432 — на этой машине 5432 уже занят нативной службой Windows postgres.exe. `DATABASE_URL` в `backend/.env` уже настроен на 5433, не меняй обратно.

## Дизайн — обязательные правила

Выведены болезненно, не отступать без явной причины:

- **Никаких эмодзи как иконок.** Только настоящие inline SVG (сейчас источник — Lucide, ISC-лицензия, скачано в `frontend/src/icons/Icons.tsx`). Эмодзи-иконки и юникод-символы (◇ и т.п.) читаются как дешёвый ИИ-дизайн.
- Тёмная тема: фон `#0A0A0F`, поверхности `#14121b`/`#17151f`. Акцент — фиолетовый градиент `#7C3AED → #A855F7`. Золотой `#F59E0B → #FBBF24` — для побед/выплат. `danger` `#EF4444`.
- Валюта Gram — иконка «алмаз» (`GemIcon`), не текст и не эмодзи. Telegram Stars — иконка звезды (`StarIcon`), закрашенная золотым.
- Интерактив: `active:scale-[0.96..0.97] transition-transform` на всех кнопках + `hapticImpact()` (`frontend/src/telegram/haptics.ts`) на нажатие — это требование из исходного ТЗ (раздел 10.2), не опция.
- Референс-скриншоты конкурентов (Darilo/Rolls/Balls) — только для подсказки паттернов UX (колесо, ракета в Краше и т.п.), их брендинг/арт не копировать.
- Баннеры/иллюстрации для игр (обложки) — пользователь загружает сам, когда дойдём до этого подпроекта. Не выдумывай замену без спроса.

## Тестирование — TDD, без исключений

Для каждой задачи: сначала пишется тест → прогоняется и должен упасть по ожидаемой причине → пишется минимальный код → тест прогоняется и должен пройти → коммит. Не пиши реализацию раньше теста. Если тест падает не по той причине, что ожидалась (например, конфликт портов, а не отсутствие кода) — сначала разберись в реальной причине, не подгоняй тест под симптом.
